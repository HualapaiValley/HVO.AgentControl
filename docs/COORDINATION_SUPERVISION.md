# Coordination supervision

The C# `CoordinatorService` owns the heartbeat and scheduling lifecycle. OpenCode is a bounded decision helper; finishing a model response does not stop continuous supervision. The hosted two-second timer independently runs supervision and decision scheduling, catches exceptions from both, and retries failed recovery persistence on subsequent ticks. A persisted heartbeat is refreshed every 30 seconds, including an intentional owner pause.

New coordinations in the UI default to **Keep supervising until I pause or stop**. API callers can select `continuousSupervision: true` and `turnWindowMinutes` (1–1440, default 60). `maxRounds` grants 1–100 model calls per window. Existing API callers retain bounded-task semantics. During supervision, lifetime `Round` is never reset. Exhausting a window changes the state to `WaitingBudget`: worker monitoring continues, and the C# timer opens the next window automatically. Restart uses the saved deadline and grants one new allowance, without accumulating missed windows or replaying assignments. The model's `complete` result ends its current planning pass and leaves the supervisor waiting for relevant evidence or the idle-capacity timer.

The coordination page shows the service heartbeat, remaining model turns, next allowance window and scheduler reason. The idle-capacity timer rechecks available workers; command completion, questions and bounded progress observations trigger earlier decisions. Owner-assigned prompts created on participating workers during the run are included as evidence with their original provenance, so direct intervention cannot make the coordinator believe those workers have no assignment. Earlier tasks and other workers are excluded.

An explicit owner pause or stop wins over automatic timers. Uncertain delivery still requires reconciliation; monitoring must not replay it to appear busy. Provider cooldown gates remain independent of model-turn windows. Turn allowances limit calls, not monetary spend or provider token quotas; #82 tracks those limits.

For an existing paused run, `POST /api/v1/coordinations/{id}/renew` accepts an idempotent request `id`, `expectedRevision`, `additionalRounds`, replacement `instruction`, `continuousSupervision`, and `turnWindowMinutes`. This enables supervision on a legacy exhausted run without replacing its identity or losing active assignments, model sessions, decision receipts or update schedules. The UI exposes the same checkpoint operation. Each owner grant permits at most 100 remaining turns. The previous instruction and allowance are retained in an audit event. Unresolved coordinator delivery cannot be discarded through this endpoint.

Acceptance evidence covers the real hosted timer reopening an exhausted window after restart without an owner or model renewal; preservation of in-flight assignments; no allowance accumulation; owner pause/stop; model completion followed by an idle-capacity recheck; owner-assigned work visibility; and authenticated idempotent checkpoint updates. This does not yet implement the dependency-aware backlog database, exact-head merge gate or independent-review identity gate tracked by #78, #70 and #8.
